# Bedrock setup (Geyser + Floodgate)

This plugin does **not** push the Bedrock pack itself — Geyser handles
Bedrock resource-pack delivery on its own, and that's the right place for
it to live, since Geyser (not your Paper plugin) is what your Bedrock
players actually connect to.

## 1. Install Geyser + Floodgate on your proxy/server

Standard install, nothing custom:
- Geyser-Spigot (or Geyser-Standalone if you run Geyser separately)
- Floodgate (lets Bedrock players join without Xbox auth linking)

Verify Geyser's version supports your Paper 26.3 server; Geyser's own
compatibility table is the source of truth — check it again at install time
since it's updated continuously and this plugin can't verify it for you.

## 2. Install the resource pack

Copy `respack-bedrock.mcpack` into Geyser's `packs/` folder
(typically `plugins/Geyser-Spigot/packs/`). Geyser auto-detects and force-
applies any valid pack placed there to every Bedrock client that connects —
nothing else to configure for delivery itself.

## 3. Install the custom-item mapping

The file `geyser_custom_items_christmas.json` (also inside the .mcpack, at
its root) tells Geyser "when the Java server shows a `minecraft:paper` with
custom_model_data N, show Bedrock players this icon + this attachable
geometry instead." Place it per Geyser's custom-items documentation —
check Geyser's own wiki for the exact config path/key for your Geyser
version, since this has moved before between releases and I can't verify
the current location without a live install to test against.

## 4. Known limitations, stated plainly

- Bedrock players see the same furniture positions, placement, rotation
  and removal as Java players — the entities (ArmorStand/ItemFrame) and
  their locations are identical. What differs is only the rendering path
  of the held item's geometry.
- The attachable geometry was generated by directly converting the Java
  model's cuboids into Bedrock's bone/cube format with a straightforward
  coordinate shift (see `gen_bedrock.py` for the exact transform). I have
  not been able to load this on a real Bedrock client in this environment,
  so treat the first install as a test pass: check scale, position offset
  from the hand, and whether any piece looks flipped or mis-scaled, and
  adjust the `origin`/`pivot` values in the `.geo.json` files if so.
- If you want genuine 1:1 visual parity with Java's display-entity-based
  furniture look instead of the held-item look, that requires installing
  an additional, separately-maintained, explicitly experimental Geyser
  extension (e.g. projects like STEMCraft's or CraftBridge's display-entity
  bridges) on the Geyser side — outside the scope of what a Paper plugin
  alone can deliver, and those projects themselves note open bugs with
  animated/updating displays. I did not build or bundle one of these,
  since I can't test or vouch for something I haven't verified working.
